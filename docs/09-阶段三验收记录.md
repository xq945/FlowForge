## 4. 设计调整（相对阶段一文档）

| 调整 | 原因 |
| --- | --- |
| 执行实例由调度服务**通过 Feign 请求执行服务创建**，而非直接写库 | `workflow_execution` 归执行服务所有，跨库直写会破坏服务边界 |
| 版本快照由调度服务读取后**随请求传给执行服务** | 执行服务运行时不依赖工作流服务，实例创建即自包含 |
| `workflow_execution` 增加 `edges_snapshot` 字段 | 执行引擎要重算可达性，必须有图的形状 |
| `node_execution` 增加 `config_snapshot` / `retry_initial_ms` / `retry_max_ms` / `timeout_ms` | 执行记录必须自包含，历史执行要能解释自己 |
| 条件节点用「field + operator + value」结构化配置 | 避免引入表达式引擎的执行风险 |
| 完成计数改为**重算覆盖**而非逐个自增 | 重算天然幂等，异常回滚后下一轮自动修正 |
| 节点/边/类型放到 `common.contract` | 跨服务契约，不是业务实体（不需要搬进各自的 service 层） |

## 5. 过程中发现并修复的问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| **`/actuator/health` 返回 401** | Spring Boot 绑定集合属性时先**清空再填充**，写在字段上的默认白名单被配置文件整体覆盖 | 默认放行项改由自动配置在装配时合并，属性里只放业务路径 |
| HTTP 节点输出把状态码和响应体混在 `status` 字段 | `{"status": 200, "body": "..."}` 导致条件节点无法取 body 内字段 | 拆成 `httpStatus` 与解析后的 `body` |
| 孤立节点永远「可达」 | 入度为 0 的节点都被当作起点，可达性检查对它恒为真 | 改为检查「既无入边又无出边」，同时允许多起点并行 |
| MyBatis-Plus 分页插件找不到 | 3.5.9 起分页与 JSqlParser 从 starter 中拆出 | 显式引入 `mybatis-plus-jsqlparser` |
| 调度服务启动要求数据源 | 阶段三调度服务没有自己的表 | 暂时移除 mybatis/mysql 依赖，阶段四接周期任务时加回 |
| 网关 `POST/GET /api/executions` 冲突 | 触发归调度、查询归执行 | 用 Method 谓词区分，带谓词的路由排在通配路由之前 |
